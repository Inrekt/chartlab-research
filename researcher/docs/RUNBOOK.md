## 2. Тревоги: что означает и что делать

### 🚨 «Прогон ОСТАНОВЛЕН намеренно... КАТАЛОГА НЕТ»
**Что это.** Предохранитель поймал отсутствие данных. Без него испытания дали
бы ноль сделок, и это записалось бы в журнал как ВЫВОД О РЫНКЕ, а не как
поломка. Именно так однажды погибли 212 испытаний фандинга.
**Что делать.** Проверить, что приватный data-репо на месте и в воркфлоу задан
`COLLECT_DIR`. Данные лежат в `~/.chartlab/data-repo/market/`.

### 🚨 «Пространство гипотез исчерпано»
**Что это.** Все разрешённые комбинации уже проверены (468 на таймфрейм).
Ночь останавливается, чтобы не изображать работу впустую.
**Что делать.** Это НЕ повод ослаблять ворота. Нужна пре-регистрация нового
семейства с полем «кто платит» — см. `researcher/docs/family-*.md` как образец.
До этого ночи будут падать каждый раз, и это правильно.

### 🚨 «Предполётная проверка: корпус свечей просрочен»
**Что это.** Последний бар корпуса старше 14 суток. Файлы при этом на месте —
ловится именно ПРОСРОЧЕННОСТЬ, а не отсутствие. Ровно так корпус однажды
простоял две недели мёртвым и никто не заметил.
**Почему это останавливает ночь.** Инкубатор тянет свежие бары прямо с биржи,
а скрин считал бы по замороженному корпусу: кандидат отбирался бы на одном
рынке, а догонялся на другом, и форвард измерял бы не то, что отбор.
**Что делать.** Посмотреть шаг «Top up corpus from exchange» в последнем
прогоне — он умышленно `continue-on-error`, поэтому его падение видно только
здесь. Локально дозаписать хвост:
```bash
cd /Users/user/chartlab-research && npx tsx researcher/collect-candles.ts --source perp --tf 1h,4h
```

### ⚠️ «корпус отстаёт на N сут» (в логе, ночь продолжается)
**Что это.** Отставание от 3 до 14 суток. Биржа бывает недоступна, и ночь на
пятилетней истории с двухдневным хвостом остаётся честной ночью.
**Что делать.** Ничего срочного. Если предупреждение держится третий день
подряд — сборщик умер, лечить как случай выше, не дожидаясь порога остановки.

### 🚨 «Дамп журнала вырос до N МиБ»
**Что это.** Приблизились к жёсткому лимиту GitHub в 100 МиБ на файл.
**Что делать.** Перенести журнал на свой сервер (лимита нет) ИЛИ разбить по
месяцам. Удалять данные НЕЛЬЗЯ — журнал append-only, и отрицательное знание
(где копать бесполезно) стоит дороже места.

### ⚠️ Ночь не запустилась / опоздала
**Что это.** GitHub роняет расписания молча, это его известное свойство
(06.08.2026 ночи не было вовсе, 07.08 опоздала). Не наша поломка.
**Что делать.** Перезапустить вручную:
```bash
cd /Users/user/chartlab-research && gh workflow run nightly.yml
```

### ⚠️ Тишина дольше суток
Самый опасный случай: сломался тот, кто должен сообщать о поломках.
Проверить по разделу 1.

## 3. Что УЖЕ сделано (не переделывать)

Всё проверено `npm run typecheck` + `npx vitest run` и закоммичено.

## 4. Что ОСТАЛОСЬ — по приоритету

Порядок = очередь вылета: что ниже, отваливается первым.

### Блок выживания (ломается молча, доделать нельзя потом)
1. **Сторож на пропущенные ночи** (healthchecks.io, бесплатно) + тревоги в
   Telegram + автокоммит раз в неделю (GitHub отключает расписания в
   репозиториях без активности ~60 дней). **Ждёт владельца:** нужен аккаунт
   и токен бота.

### Наука (без этого не будет находок)
2. ⛔ **Пакет ворот `GATE_VERSION=6` — ЖДЁТ РЕШЕНИЯ ВЛАДЕЛЬЦА, не начинать.**
   Стенд мощности (п. «сделано») показал, что состав пакета был неверным:
   - **`varSR` по одному семейству — единственный работающий пункт.** Планка
     пропорциональна √varSR, всё остальное второго порядка. Но это правка
     НЕПРИКАСАЕМЫХ ворот, и решение не за исполнителем. Обоснование, замер и
     заранее записанный ожидаемый эффект: `docs/dsr-power-preregistration.md`;
   - `nEffective` по родословной — **сам по себе не даёт ничего** (0% → 0%):
     планка растёт как √(2·ln N), логарифмически. Ценен только ПОВЕРХ varSR
     (10% → 42% при δ=0.25);
   - фантомные 1d-кластеры — **0.5% планки, из критического пути вычеркнуть.**
     И само число из приговора коллегии неверно: не 2780, а 652 (остальные
     2128 содержат также испытания 1h/4h и законны);
   - `gate_temporal` без огрызков лет, издержки по тирам, lookahead в тирах,
     веса уникальности — остаются в пакете как корректность, но на мощность
     почти не влияют (стенд: эти ворота пропускают 96–100% при δ ≥ 0.18).
   Порядок обязателен: пре-регистрация заморожена → пакет ОДНИМ коммитом →
   и только ПОТОМ смотреть, кто из журнала прошёл бы. Иначе это подгонка
   планки под уже увиденных.
3. **Дымовой прогон ворот OOT** — в журнале НОЛЬ записей, код ни разу не
   исполнялся на живых данных. (Уилсон впервые исполнен стендом мощности:
   пропускает 100% при δ ≥ 0.18, но на синтетике, не на свечах.)
4. **Дымовой прогон инкубатора** — `incubations = 0`, `paper_trades = 0` за всю
   историю. Половина машины никогда не работала.
5. **Пре-регистрация свип-семейства** (край владельца) + `whoPays`. Без неё
   ночи падают на исчерпанном пространстве. Доработки из ресёрча: сессионный
   экстремум вместо N-барного, фильтр близости к круглому числу, тайм-фильтр
   окна отработки, посев топ-25/30 символов вместо топ-8.

### Решения владельца, ещё не выполненные
6. **Переезд на свой сервер Hetzner** (одобрен). Причина: GitHub роняет

7. **Репозиторий `chartlab-research` → приватный** (одобрен). Внутри

   перестанет читать `status.json` с raw.githubusercontent — нужен
   санированный публичный срез (агрегаты без имён сетапов и параметров).
8. **Баланс API + автопополнение**: $30 Anthropic (порог долива $20) +

10. **Пометка проп-пригодности** вместо приговора (~0.3 дня, после первого

### Взять из чужого арсенала (дёшево, доказано)
11. **Три ворот, которые продают за деньги, а стоят день работы:**
   перемешивание порядка сделок (устойчив ли результат к удаче), тест шумом
   (выживет ли при сдвинутых ценах), бенчмарк против случайной стратегии с
   той же статистикой входов.
12. ⚠️ **Point-in-time дисциплина для любого ИИ-компонента.** Замерено
   независимо: у LLM-стратегий доходность +20.7% внутри окна обучения
   превращается в −1.0% за его границей. Правило: тестовое окно строго ПОСЛЕ
   границы знаний модели, иначе меряем её память, а не край.

## 7. Незыблемые правила — почему они такие

Не «перестраховка», а причина существования проекта.

- **Пре-регистрация ДО кода.** В клинических испытаниях обязательная
  предварительная регистрация обрушила долю «положительных» результатов
  с 57% до 8% — то есть перестала производить иллюзии.
- **Ворота не ослаблять.** Каждая проверка отсеивает свой вид самообмана.
  Ослабить — значит начать принимать случайность за находку.
- **Слепой перебор заморожен.** 56 000 испытаний, 0 находок. Это не неудача:
  планка растёт как √(2·ln N), и перебор сам себя убивает.
- **ИИ не принимает торговых решений.** Замерено независимо: у LLM-стратегий
  Шарп падает на 51–62% за границей знаний модели — она вспоминает, а не
  предсказывает.
- **Проп-счёт — не инструмент проверки гипотез.** Проверяет инкубатор
  (минимум 120 дней форварда), проп получает только выпускников.

ворота пропускают настоящий край. Замер мощности показал, что при нынешних

Пересчитывать их до этого решения бессмысленно — это была бы арифметика
поверх сломанного прибора.

Машина ломается 3–4 раза в год, когда внешний мир меняет правила. Цель — не
«никогда не сломается», а **ломается громко, а не молча**. Молчание — самый
опасный отказ: именно так корпус простоял две недели, а фандинг был невидим
212 испытаний.
