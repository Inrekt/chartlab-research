# Пре-регистрация: мощность ворот дефляции и пакет GATE_VERSION=6

**Дата: 2026-08-09.** Записано ДО просмотра того, кто из реальных кандидатов
журнала прошёл бы при изменённых параметрах. Порядок принципиален: ворота
дефляции — НЕПРИКАСАЕМЫЕ, и правка планки после взгляда на выживших есть
подгонка второго порядка, невидимая для всех остальных проверок.

## Что измерено

`researcher/recall.ts` — стенд мощности. Синтетические сделки с заранее
заложенным Шарпом на сделку δ (по NET-доходности, то есть после издержек)
прогоняются через настоящие ворота. Доля выживших — мощность батареи.

Параметры взяты из живого журнала, а не назначены:

| Величина | Значение | Откуда |
|---|---|---|
| `nEffective` | 8445 | среднее по 521 записи `gate_dsr` |
| `varSR` | 0.0158 | **медиана** тех же записей |
| сделок на кандидата | 1000 | порядок величины ночных партий |
| символов | 16 | `STAGE_A_SYMBOLS` |
| лет | 5 | окно корпуса |

⚠️ Медиана, а не среднее: `varSR` скошен вправо (p10 0.0045, p50 0.0158,
p90 1.158; среднее 0.185). Среднее описывало бы ночь, которой не было.

## Результат: ворота глухи к любому реалистичному краю

200 прогонов на δ, медианные параметры журнала:

|---|---|---|
| 0.10 | 1.6 | **0.0%** |
| 0.18 (входной порог инкубатора) | 2.8 | **0.0%** |
| 0.20 | 3.2 | **0.0%** |
| 0.25 | 4.0 | **0.0%** |
| 0.35 | 5.5 | **0.0%** |
| 0.40 | 6.3 | 0.0% |
| 0.50 | 7.9 | 28% |
| 0.60 | 9.5 | 72% |
| 0.80 | 12.6 | 99% |

**Ворота включаются при δ ≈ 0.5, то есть годовом Шарпе около 8.** Для
сравнения: у Medallion Шарп порядка 2. Все остальные ворота при δ ≥ 0.18
пропускают 96–100% — узкое место ровно одно и оно названо.

Это отвечает на главный открытый вопрос проекта. Результат «56 374 испытания
→ 0 находок» имел две одинаково правдоподобные причины: поле выжжено или
прибор глух. Измерение показывает, что **прибор глух** — при таких параметрах
он не пропустил бы и настоящий край. Про выжженность поля результат не
говорит ничего; он просто не мог её измерить.

## Что дают починки учёта — и чего не дают

100 прогонов на конфигурацию:

| Конфигурация | δ=0.20 | δ=0.25 | δ=0.35 |
|---|---|---|---|
| как сейчас (N=8445, varSR=0.0158) | 0% | 0% | 0% |
| минус кластеры только-1d (N=7793) | 0% | 0% | 0% |
| счётчик по родословной (N=500) | 0% | 0% | 0% |
| varSR по одному семейству (÷4) | 1% | 10% | 81% |
| родословная + varSR÷4 | 15% | **42%** | 96% |
| родословная + varSR÷10 | 68% | 97% | 100% |

### Три вывода, отменяющие прежние приоритеты

1. **Фантомные 1d-кластеры — не рычаг.** И само число было неверным:
   в приговоре коллегии стоит «2780 фантомных кластеров из 9640 (28.8%)»,
   но 2128 из них содержат ТАКЖЕ испытания 1h/4h и существуют законно.
   Исчезли бы только **652** кластера, и планка сдвинулась бы на 0.5%
   (sr0 0.4801 → 0.4776). Учёт поправить стоит, но из критического пути
   вычёркивается.

2. **Счётчик по родословной сам по себе не даёт НИЧЕГО** (0% → 0%).
   Планка растёт как √(2·ln N) — логарифмически: даже обрезание N с 8445 до
   100 умножает её лишь на 0.66. Ценность родословной проявляется только
   ПОВЕРХ починки varSR (10% → 42%), и это её настоящая роль.

3. **Единственный рычаг — `varSR`**, потому что планка пропорциональна
   √varSR. Всё остальное — второй порядок.

## Что предлагается и чем это обосновано

`screen.ts:406` считает `varSR` как разброс Шарпа по ВСЕЙ ночной партии,
где рядом стоят разные механизмы. Формула Бейли–Лопеса де Прадо просит
дисперсию оценок Шарпа внутри СЕМЕЙСТВА множественных проверок — то есть
разброс ВЕЗЕНИЯ однотипных попыток. Разброс между механизмами — это
настоящее различие, а не шум отбора, и его подстановка завышает
оценку случайного максимума.

⚠️ **Честно о размере эффекта.** Замер по журналу (521 запись `gate_dsr`,
разбивка по ночам и семействам): дисперсия внутри семейства относится к
дисперсии по смеси примерно как **0.42** (медиана по 7 ночам для
`breakout` — крупнейшего семейства; разброс 0.11…0.56). То есть ÷4 —
верхняя граница правдоподобного, а **÷10 измерением НЕ подтверждается** и
предлагаться не может.

Замер сделан на выживших до ворот DSR, то есть на суженной выборке — обе
дисперсии занижены, и отношение может быть смещено. Это ограничение
измерения, а не аргумент в пользу большего деления.

**Ожидаемый эффект, зафиксированный ЗАРАНЕЕ:** при varSR по одному семейству
и счётчике по родословной мощность при δ=0.25 составит **40±15%**, при
δ=0.20 — **15±10%**. Если после внедрения реальная доля прошедших окажется
заметно выше — это признак того, что подставлена не та величина, а не удачи.

## Дополнение того же дня: прогон без короткого замыкания

Ночной гаунтлет замыкается накоротко — упавший на первых воротах до остальных
не доходит. Поэтому доля выживших по цепочке не отвечает на вопрос «а сами-то
эти ворота строгие?»: она смешивает строгость с очерёдностью. Стенд теперь
считает ВСЕ ворота на каждом кандидате.

Одиночные убийства (ворота были ЕДИНСТВЕННОЙ причиной смерти), 200 прогонов:

| δ | активность | широта | стресс | время | **дефляция** | Уилсон |
|---|---|---|---|---|---|---|
| 0.20 | 0 | 0 | 0 | 0 | **192** | 0 |
| 0.25 | 0 | 0 | 0 | 0 | **199** | 0 |
| 0.35 | 0 | 0 | 0 | 0 | **200** | 0 |
| 0.60 | 0 | 0 | 0 | 0 | **59** | 0 |

**Пять ворот из шести не стоят в мощности ничего.** Настоящий край они
пропускают целиком (маргинальная доля 98–100%). Вся потеря — в одних воротах.

⚠️ Это НЕ довод убрать пять ворот. Их работа — резать ЛОЖНЫХ кандидатов, а
стенд прогоняет только настоящие: он меряет ЦЕНУ ворот, а полезность меряет
нуль-гаунтлет (`selfcheck.ts`, норма — 0 проходов из 20). Правильный вывод
ровно один: **менять надо только дефляцию, остальные ворота трогать незачем**,
и любая правка «заодно» тратит бюджет доверия впустую.

Заодно это снимает возражение из внешнего разбора о том, что девять условий,
перемноженных в одно, задавили мощность самой своей конъюнктивностью. На
уровне сделочных ворот конъюнкция не стоит ничего — стоит одно слагаемое.

## Чего этот стенд НЕ измеряет

Ворота нуль-модели, плато и out-of-time здесь не проверяются — им нужны
свечи и соседи по параметрам. Мощность батареи ЦЕЛИКОМ не выше показанной,
и приведённые проценты — верхняя граница, а не оценка.

Отдельно: `gate_wilson` и `gate_oot` за всю историю журнала не исполнялись
ни разу (0 записей в `evals` при 56 374 испытаниях) — до них никто не
доходил. На стенде Уилсон пропускает 100% при δ ≥ 0.18, но это первое
исполнение этого кода на данных вообще.

## 🔴 Поправка к предложению: глухих ворот ДВОЕ, и второй порог невидим

Найдено адверсарной проверкой того же дня. Починка `varSR` в одиночку даст
**ноль инкубируемых**, и вот почему.

`incubate.ts`: `sigma = max(seedSigma, SIGMA_FLOOR=0.5)`, `mu1 = netExpectancy/2`
(скептичная половина Бентера), отказ при `delta = mu1/sigma < ENTRY_GATE_DELTA
= 0.18`. Замеренная σ R-мультипликаторов у нас 1.04 (1h) и 1.19 (4h), то есть
пол 0.5 не связывает никогда, и условие схлопывается в тождество:

> **входной порог инкубатора ≡ tradeSharpe ≥ 0.36**

Лучший `tradeSharpe` за всю историю журнала — **0.2539**. То есть даже если
ворота дефляции пропустят кандидата с δ=0.25, инкубатор отвергнет его
следующей строкой. Порог нигде не записан в этом виде, ни в одной
пре-регистрации не назван и потому не обсуждался.

Это не довод «ослабить заодно и его». Это довод считать пороги ПАРОЙ:

| | требует Шарпа/сделку | статус |
|---|---|---|
| ворота дефляции (varSR как сейчас) | ~0.54 | измерено стендом |
| ворота дефляции (varSR по семейству, ÷4) | ~0.29 | расчёт |
| **вход в инкубатор** | **0.36** | тождество, не настройка |
| лучший кандидат за историю | 0.25 | факт журнала |

После починки varSR связывающим становится ВХОД В ИНКУБАТОР, и разрыв
сокращается с ×2.1 до ×1.4 — но не закрывается. Честная формулировка
предложения владельцу поэтому такая: **починка varSR необходима, но одна не
достаточна**; вопрос о `ENTRY_GATE_DELTA` придётся решать отдельно и он
требует своей пре-регистрации (порог выведен из E[N] ≤ 150 сделок при
α=0.05, β=0.1 — то есть из длины теста, а не из рынка, и менять его значит
менять длину инкубации).

Обязательное следствие для кода: два порога живут в разных файлах и обязаны
сравниваться. Инвариант «вход в инкубатор не строже финальных ворот скрина»
должен быть тестом, иначе они снова разъедутся молча.

## Решение владельца

Изменение `varSR` касается НЕПРИКАСАЕМЫХ ворот. Оно не принимается
исполнителем: измерение и обоснование — здесь, решение — за владельцем.

Если решение «да», порядок обязателен:
1. этот документ заморожен датой (сделано);
2. пакет GATE_VERSION=6 идёт ОДНИМ коммитом: varSR по семейству + счётчик по
   родословной + учёт кластеров;
3. только ПОСЛЕ этого смотрим, кто из журнала прошёл бы.

Если решение «нет» — ворота остаются как есть, и это тоже осмысленный
выбор: мощность 0% при δ=0.25 означает, что машина не выпустит ничего, но
и не выпустит ложного. Тогда честная формулировка проекта меняется: он ищет
не «край», а «край с годовым Шарпом ≥ 8», и таких почти не бывает.

## РЕЗУЛЬТАТ ВНЕДРЕНИЯ (2026-08-09, решение владельца — «да»)

Пакет внедрён ОДНИМ коммитом, порядок соблюдён: документ был заморожен до
правки, эффект замерен после.

**Версия ворот — 7, а не 6.** Шестёрку в тот же день занял перевод SPRT на
дневные наблюдения. Общий номер пометил бы 108 сегодняшних испытаний как
измеренные новым прибором, хотя мерились старым. Версия — это прибор.

### Что подставлено

- `varSR` — дисперсия внутри семейства. Отношение взято ЗАМЕРЕННОЕ (**0.42**,
  то есть ÷2.4), а НЕ ÷4 из таблицы прогноза: ÷4 в самом документе назван
  «верхней границей правдоподобного», и подставлять границу вместо оценки
  значило бы выбрать удобное.
- `nEffective` — кластеры своего семейства, без 652 фантомных «1d».
- предохранитель: семейству нужно ≥5 измеримых кандидатов, иначе берётся
  общепартийная дисперсия, то есть СТАРОЕ, более строгое поведение.

### Мощность после правки (200 прогонов, varSR=0.0066)

| родословная | δ=0.20 | δ=0.25 | δ=0.35 |
|---|---|---|---|
| 10 кластеров (новое пре-зарегистрированное семейство) | 65% | **94%** | 100% |
| 50 | 20% | 55% | 99% |
| 500 | 1% | 9% | 78% |
| 802 (breakout — наследие слепого перебора) | 0% | 6% | 70% |
| *было (9650, varSR 0.0158)* | *0%* | *0%* | *0%* |

**Прогноз 40±15% при δ=0.25 не подтвердился в обе стороны сразу**, и это
важнее самого числа: он был записан для ОДНОЙ конфигурации, а мощность
оказалась функцией размера родословной. При N=500 вышло 9% (ниже полосы,
потому что прогноз считал по ÷4), при N=10 — 94% (много выше). Урок на
будущее: заранее фиксировать надо не одно число, а зависимость.

### 🔴 Обратная сторона, названная сразу: множественность МЕЖДУ семействами

Планка теперь тем ниже, чем меньше семейство. Это правильный стимул — он
вознаграждает ровно ту дисциплину, на которой стоит проект: мало гипотез с
высоким приором вместо миллиона с плоским. Но он же создаёт очевидную дыру:
**наплодить полсотни крошечных семейств значит выдать себе низкую планку.**

Сейчас это НЕ прикрыто. `familiesTried` пишется в журнал рядом с каждым
вердиктом (12 семейств на сегодня), чтобы дыра была видимой, а не молчаливой.

Правильная конструкция — контроль ошибки на ДВУХ уровнях: DSR внутри
семейства (сделано) плюс контроль доли ложных открытий МЕЖДУ семействами
(не сделано). BH-FDR в воронке есть, но применяется к партии одной ночи, а
не к списку семейств за историю проекта.

**Требование, вступающее в силу немедленно:** пока межсемейный контроль не
построен, каждое новое семейство обязано иметь пре-регистрацию с механизмом
и платящей стороной — то есть высокий приор, оплаченный мышлением, а не
перебором. Ровно это и есть замена статистической поправке. Массовое
порождение семейств без пре-регистрации при новых воротах ЗАПРЕЩЕНО: это
вернуло бы слепой перебор через чёрный ход и обесценило бы починку.
